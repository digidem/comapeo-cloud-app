# QA #359 — report-branding cross-browser CI recovery

## Scope

Validate the maintenance fix for issue #359: the report-branding E2E path must remain usable while network requests are blocked, including WebKit, and pull-request CI must exercise that regression path in Firefox and WebKit before merge.

This change is test/CI-only. It does not intentionally change production application behavior or visual design.

## Prerequisites

- Repository dependencies installed from the lockfile.
- Docker available locally so WebKit can run with the Playwright system dependencies used by CI.
- The checked-out branch/head is the exact revision being evaluated.

## Automated QA

Run:

```bash
./scripts/qa/359-report-branding-e2e.sh
```

The helper performs:

1. focused `ReportBrandingDialog` and repository guardrail unit tests;
2. TypeScript, targeted ESLint/Prettier, and the production CI build;
3. Chromium and Firefox report-branding E2E with retries disabled;
4. WebKit E2E with retries disabled using the representative PR ordering (`app-db.e2e.ts` before `report-branding.e2e.ts`) inside the official Playwright container matching the installed Playwright version.

## Expected results

- All automated checks exit successfully.
- The mobile report-branding test can upload, preview, save, and reopen branding while network requests are blocked.
- The accessible `Organization logo` image assertion remains enabled in all three engines.
- No retry increase or test-timeout increase is required.
- `.github/workflows/ci.yml` includes `tests/e2e/report-branding.e2e.ts` in the Firefox/WebKit PR subset.
- Exact-SHA GitHub `build-e2e` is green on the PR head.

## Failure conditions

Treat the QA as failed if any of the following occur:

- WebKit reports `Unable to process logo image`, `NotReadableError`, `InvalidStateError`, or a missing `Organization logo` after upload.
- Chromium, Firefox, or WebKit needs additional retries or a larger timeout to pass the branding regression path.
- The PR cross-browser CI subset no longer includes `report-branding.e2e.ts`.
- Any relevant exact-SHA CI check fails or remains pending.

## Root-cause evidence

The authoritative failing `main` Actions run reached `Report logo configured` in WebKit but never exposed the `Organization logo` after `browserContext.setOffline(true)`, while the same flow passed in Chromium, Firefox, and desktop WebKit. Replacing whole-context offline mode with explicit request abortion preserves browser-local file/image processing, and blocking service-worker control for this local-only flow makes that request boundary observable and deterministic to Playwright. The test also waits for `domcontentloaded` rather than the browser's full `load` event before continuing with locator-driven assertions, removing unrelated cross-engine navigation delay without increasing retries or timeouts.

For extra confidence on the previously failing WebKit path, run it repeatedly with retries disabled:

```bash
docker run --rm --ipc=host \
  --user "$(id -u):$(id -g)" \
  -e VITE_PREVIEW=1 \
  -v "$PWD:/work" -w /work \
  mcr.microsoft.com/playwright:v1.60.0-noble \
  npx playwright test tests/e2e/report-branding.e2e.ts \
    --project=webkit --grep "remains usable offline" \
    --retries=0 --repeat-each=3 --workers=1 --reporter=list \
    --output=/tmp/comapeo-qa-359-webkit-repeat
```

Expected: all three repetitions pass without retry or timeout changes.

## Cleanup / reset

The QA helper uses `docker run --rm`, runs the container as the current user, and keeps Playwright output in the disposable container's `/tmp`. It does not leave a persistent browser container or preview server. If a run is interrupted, remove only test artifacts created by that run; do not reset or clean unrelated worktrees.

## Known limitations

- GitHub Actions remains the authoritative final signal for the full repository E2E suite on the exact PR SHA.
