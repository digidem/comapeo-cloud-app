# QA Script — Issue #325: #288 review follow-ups

## Scope

This QA validates the six maintenance follow-ups from issue #325:

1. Oversized non-sensitive telemetry containers are truncated without globally redacting safe event primitives.
2. Truncated sensitive subtrees and exhausted sensitive-value collection still fail closed.
3. Secret telemetry header keys use the same normalized form as runtime key matching, including proxy authorization and API-key headers.
4. Root event Sentry `tags` keep sanitized, length-bounded keys while every value is redacted; nested CoMapeo/domain `tags` remain fully redacted as a sensitive container.
5. Authenticated media derives credential scope from configured archive servers plus the active base URL, so an archive credential is never attached to an unmatched origin even if the legacy `tier` field is stale/default.
6. `AGENTS.md` documents `comapeo:credentialCleanupVersion` as an intentional reset control-plane storage exception.

There is no new user-facing UI in this issue. Human QA exercises existing archive media and telemetry paths to prove the maintenance changes did not regress them.

## Manual preview / staging acceptance

Record the exact PR head SHA, preview URL, browser, and archive used.

### 1. Authenticated image loading

1. Open the exact PR preview.
2. Connect/reconnect a disposable archive containing at least one observation/category image.
3. Navigate to a screen that renders the authenticated image.
4. Confirm the image loads normally.
5. In DevTools Network, inspect the media request.

Expected:

- Matching archive media is routed through the expected authenticated archive path.
- The request uses only the credential belonging to that matching archive.
- No credential appears in the rendered URL, console output, or browser storage.

Failure:

- The image fails only on the PR preview.
- A credential is sent to a non-matching origin.
- A credential appears in URL/history/storage/console surfaces.

### 2. Authenticated audio loading

1. Open an observation with an audio attachment from the same disposable archive.
2. Play the audio.
3. Inspect the attachment request in DevTools Network.

Expected:

- Audio loads/plays successfully.
- Credential routing follows the same matching-archive boundary as images.
- No credential is attached to an unrelated origin.

### 3. Archive ↔ local switching and unmatched-origin boundary

1. With an archive unlocked, navigate through archive-backed media and confirm it loads.
2. Switch to local/non-archive content where available.
3. Trigger a media request whose origin is not one of the configured archive origins (or use the existing QA fixture/path that represents this case).
4. Inspect request headers.
5. Switch back to the archive and re-check matching media.

Expected:

- Archive media continues to authenticate correctly after switching.
- Local/non-archive media remains usable according to existing behavior.
- Unmatched-origin requests carry no active archive Authorization credential.
- Returning to the archive does not require changing or relying on the legacy `tier` field.

Failure:

- An active archive credential is attached to an unmatched origin.
- Archive/local switching leaves media stuck, stale, or authenticated against the wrong server.

### 4. Network credential inspection

During the image/audio/switching checks, inspect all related Network requests.

Expected:

- Matching archive requests have the expected archive credential boundary and proxy headers.
- Unmatched origins have no archive Authorization header.
- No credential value is visible in query strings or response bodies generated by the app.

Any credential sent to the wrong origin is a release blocker.

### 5. Staging Sentry / telemetry verification (when available)

Trigger a harmless test event/transaction on staging that includes:

- safe event primitives such as event id/platform/timestamp,
- a non-sensitive array/object larger than the sanitizer entry bound,
- object-valued tags,
- a synthetic credential-like header/value canary.

Expected in Sentry:

- The event remains ingestible and keeps safe primitives even though the non-sensitive container is truncated.
- Tag keys remain present/filterable, while tag values are `[REDACTED]`.
- Credential/header canaries are absent.
- Sensitive truncation remains fail-closed.

Failure:

- The whole event becomes unusably over-redacted merely because a safe container is large.
- Tag structure is replaced by a scalar instead of retaining keys.
- Any credential/header canary is visible.

If staging Sentry cannot be accessed, mark this item `NOT RUN — environment unavailable` and retain automated sanitizer/Sentry test evidence plus CI.
