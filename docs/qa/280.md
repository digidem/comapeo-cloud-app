# QA Script — Issue #280: Persist authored layers in SavedMap

## Scope

This QA validates issue #280 end to end:

- canonical authored-layer persistence in `SavedMap.layers`
- lossless recovery of corrupt/future persisted layer entries
- non-destructive open/cancel behavior
- explicit invalid-row removal followed by intentional save
- stable layer IDs across visibility/order/style changes
- package lifecycle preservation vs invalidation
- persisted authored layers flowing into SMP generation without silent dropping
- direct #222 GeoJSON import becoming the #279 authored-layer model
- offline Preview and active-map rendering for the permanent #279 vector/raster fixtures
- privacy/recovery/error UI on desktop and 375×812 mobile
- existing imported SMP / no-authored-layer compatibility

## Automated QA

## Acceptance checklist

### 1. SavedMap read/write and recovery

- Canonical writes always emit `layers: AuthoredLayer[]`, including `[]`.
- `parseSavedMapForAuthoring` rejects malformed outer/runtime fields and dangerous passthrough keys without minting a write-capable snapshot.
- Valid siblings around corrupt/future entries remain available; duplicate IDs invalidate every duplicate occurrence deterministically.
- Missing legacy `layers` behaves as an empty collection.
- `smpBlob`, `smpSize`, `scheme`, immutable identity, and safe passthrough fields survive non-package-relevant saves/open-cancel flows.
- Imported-origin rows return `SAVED_MAP_NOT_AUTHORABLE` and cannot reach the authoring write constructor.
- Name-only changes preserve package lifecycle; package-relevant map/layer changes clear stale package bytes/status metadata and return the map to `draft`.
- Restyling, hiding, reordering, or removing a layer preserves the stable ID for retained layers and never creates duplicates.

Relevant tests: `saved-map.test.ts`, `saved-map-authoring.test.ts`, `useMaps.test.tsx`.

### 2. Invalid/future recovery UI

Seed/open an authored SavedMap containing one valid canonical layer plus one future/corrupt raw layer.

Confirm:

- the valid layer still renders and appears in the controls;
- the invalid entry appears at its stored relative position;
- a safe bounded own-data `name` is shown when present, otherwise the localized **Invalid layer** fallback is used;
- opening the map alone performs no write;
- invalid entries expose Remove only, not a raw editor;
- Save changes and Download Map remain disabled while any invalid entry remains;
- Cancel leaves the original stored row byte-for-byte unchanged;
- after explicitly removing all invalid rows, Save persists only the intended valid ordered layer set.

Relevant tests: `MapScreen.test.tsx`, `AuthoredLayersControl.test.tsx`, `DownloadPanel.test.tsx`.

### 3. Contextual raster validation

For a valid raster authored layer, change the current map zoom range so the layer has no effective zoom intersection.

Confirm:

- the layer remains in the draft and remains removable/reorderable;
- the row shows the localized contextual zoom-range error;
- Save/Download are disabled;
- restoring a compatible zoom range (or removing the layer) clears the issue and re-enables normal actions.

Relevant tests: `saved-map-authoring.test.ts`, `AuthoredLayersControl.test.tsx`.

### 4. Direct GeoJSON persistence

On `/map`, add a valid GeoJSON file through **Add GeoJSON layer**, save it, reopen **Edit layers**, and confirm:

- geometry is unchanged after canonical normalization;
- file/layer name is preserved;
- visibility and ordering are restored;
- the normalized #222 visual language is preserved: orange fill/line/points, polygon fill opacity `0.16`, line width `3` / opacity `0.9`, point radius `5`, white `1.5px` point outline;
- hide/reorder/save/reopen updates the same stable IDs rather than creating duplicates;
- Cancel after reopening does not write.

Automated browser coverage: `tests/e2e/map-download.e2e.ts`.

### 5. SMP generation and offline behavior

The production PWA test must use `buildSmpBlob()` output persisted through the real map-package stores, then disable browser networking before package Preview/activation assertions.

Confirm both permanent #279 fixtures:

- `AUTHORED_VECTOR_LAYER_FIXTURE` previews offline and renders after Set active;
- `AUTHORED_RASTER_LAYER_FIXTURE` uses SavedMap bounds `[-1, -1, 1, 1]`, zoom `0..1`, and a deterministic fixed PNG response with CORS, `Content-Length`, and pinned `Response.url` during package generation;
- active MapContainer makes no external requests after the clean offline restart;
- corrupt/future persisted layers are rejected before SMP generation rather than filtered out;
- hidden canonical layers remain packaged even when not currently visible.

Automated coverage: `tests/e2e/map-offline-cold-start.e2e.ts`, `smp-download.test.ts`.

### 6. Imported/no-layer compatibility

Confirm existing imported SMP records and legacy SavedMaps without authored layers still preview/activate through their existing paths and are not rewritten through #280 authoring recovery.

The existing production offline cold-start regression in `map-offline-cold-start.e2e.ts` is part of the #280 QA script for this reason.

### 7. Privacy and visual QA

Confirm the authoring UI states that authored layer data is stored in the browser and included in the offline map package.

Review these screenshot states:

- desktop 1440×900 authored-layer recovery controls + privacy copy;
- mobile 375×812 authored-layer recovery controls + privacy copy;
- mobile 375×812 blocked Download + disabled Save while an invalid row remains.

Automated visual coverage: `tests/e2e/map-authored-layers.screenshots.ts`.

### 8. i18n

Confirm every new #280 user-facing state is extracted and translated in English, Portuguese, and Spanish, including:

- Invalid layer
- Map data could not be opened
- invalid-layer removal guidance
- raster zoom-range error
- offline-package privacy copy
- authored-layer action labels / edit-save-cancel labels

Run `npm run check:i18n` plus the locale unit tests included in the QA script.
