# QA Script — Issue #330: Compact single-line filter bar for desktop map view

Issue: #330 — `feat(data): compact single-line filter bar for desktop map view; category selection moves to temporary side sheet`

## Scope

This QA validates the desktop map-view filter surface introduced by issue #330:

- On **desktop map view** (viewport ≥ 48rem / `md`), the `topLeft` map slot renders one
  compact line — **Filters** button, active-filter chips, result count — and no longer
  renders the full `ObservationFilterBar` (no inline search/date/category inputs on the map).
- The **Filters** button badge counts active filter *dimensions* (search, start date,
  end date, categories = 1 dimension regardless of how many categories are selected;
  max 4). It is intentionally **not** the result count.
- **Filters opens a right-side drawer** on desktop (≥ 48rem) and the existing bottom
  sheet below 48rem; the drawer closes on **Apply**, **ESC**, and **outside pointer-down**.
- **Category selection is reachable only inside the drawer/sheet**, and inside the
  desktop drawer it renders as an in-drawer panel (`absolute inset-0` within the drawer),
  not a viewport-wide bottom sheet — opening it must not cover the rest of the screen.
- Each active filter renders as a **dismissible chip**; the `✕` clears exactly that
  filter via the existing setters (`setSearch('')`, `setStartDate(null)`,
  `setEndDate(null)`, `toggleCategory(name)`) without opening the sheet.
- The chip row **never wraps**: it scrolls horizontally, while the Filters button and the
  result count stay pinned and visible.
- **Mobile map view is unchanged**: bottom-left Filters button with the *result-count*
  badge, bottom-sheet filters, same behavior as before this PR.
- **Desktop grid view is unchanged**: full `ObservationFilterBar` including the inline
  category multi-select ("Filter by category" chip row), From/To inputs, and sort control.

Out of scope for this QA (unchanged by design): `useObservationFilters` logic,
`filterObservations`, `MapScreenLayout` slot mechanics, map sort control (still absent on
map view), and any persistence/reset behavior (this feature adds no storage writes).

## Prerequisites

1. Check out this branch at the candidate SHA and install dependencies
   (`npm ci` / `npm install`).
2. Start the dev server: `npm run dev` (http://localhost:5173).
3. Have a project with at least 3 observations across 2+ distinct categories, where at
   least one observation has a category and a created date, so filtering visibly changes
   the result count.
4. A browser window that can be resized continuously (for the ~800px chip-overflow step).
5. Automated coverage already green before manual QA:
   `npx vitest run tests/unit/screens/DataScreen.test.tsx tests/unit/components/shared/FilterSheet.test.tsx tests/unit/components/shared/CategoryFilterSheet.test.tsx tests/unit/components/shared/CompactObservationFilterBar.test.tsx tests/unit/hooks/useMediaQuery.test.ts`

## Test steps and expected results

### 1. Desktop map view: compact line replaces the filter panel

1. Set the window to ≥ 1024px wide. Open **Data**, switch to **map view** (grid icon).
2. Look at the top-left of the map.

**Expected:** a single compact row/card: `Filters` button (funnel icon), the result count
on the right of the same line (e.g. `3 results`), and — before you filter anything — **no**
search input, **no** From/To date inputs, and **no** category chips or category UI on the line.
The basemap switcher at the top-right stays visible and clickable (not occluded).

### 2. Drawer opens as a right-side panel and closes three ways

1. Click **Filters** on the desktop map line.
2. Close it with the **Show results** (Apply) button. Reopen.
3. Close it with the **ESC** key. Reopen.
4. Close it by clicking outside the panel (on the dimmed map area).
5. Reopen and close with the header `✕` (Close filters).

**Expected:** the panel slides in from the **right edge**, is full-height, ~380px wide,
and does **not** stretch across the screen. Each of Apply / ESC / outside-click closes it
and returns focus to the page. The panel contains, in order: title + `✕`, the
**Categories** row, search input, From/To date inputs, result count. There is **no**
bottom-sheet drag handle and no sort control. The panel never covers the top-right
basemap switcher permanently — once closed, all map controls are interactive again.

### 3. Category selection stays INSIDE the drawer

1. On desktop map view, click **Filters**, then click the **Categories** row.
2. Observe the screen outside the drawer, then select a category, then close the
   category panel (`✕` / "Close categories") and the drawer with **Show results**.

**Expected:** the category list opens **inside the drawer** — the list fills the drawer
area only, the map and the rest of the app remain visible on the left and are **not**
covered by a full-screen bottom sheet. The drawer interior dims behind the category list
and clicking that dimmed area closes the category panel. Selected categories are shown in
the Categories row count ("N selected") and, after Apply, as chips on the map line.

### 4. Chip dismissal clears exactly one filter

1. Apply a search term, a From date, a To date, and two categories via the drawer;
   click **Show results**.
2. On the map line, confirm one chip per filter: `Search: <term>`, `From: YYYY-MM-DD`,
   `To: YYYY-MM-DD`, and one chip per category (`Category: <name>`). Dates are raw ISO
   strings (no locale reformatting).
3. Click the `✕` on the `From:` chip. Then the `✕` on one category chip. Then the `✕`
   on the search chip.

**Expected:** each `✕` removes exactly that chip immediately and does **not** open the
drawer. The other chips stay. The result count updates. The badge drops when a whole
dimension is cleared (categories need **all** category chips removed before the badge
count drops). Removing a single category chip leaves the other category selected — check
by reopening the drawer: the Categories row shows the remaining count.

### 5. Badge counts dimensions, not results

1. With no filters: no badge on the Filters button.
2. Apply only a search term: badge `1`. Clear it.
3. Apply two categories (no search): badge `1` — not `2`.
4. Apply search + two categories: badge `2`.
5. Apply search + From + To + a category: badge `4` (the maximum).

**Expected:** badge shows 0 → hidden, and 1/1/2/4 for the cases above. The badge number
never equals the result count (compare against the separate `N results` text on the line).

### 6. Chip-row overflow at ~800px width

1. Resize the desktop window to **~800px × 700px** (still ≥ 48rem, so the compact line
   applies) and open the map view.
2. Apply search + From + To + 2–3 categories so the line holds 5+ chips.

**Expected:** the line stays **one line tall**. The Filters button stays at the left and
the result count stays visible at the right, both without scrolling. The chip row scrolls
**horizontally** (shift + mouse wheel, trackpad swipe, or keyboard: focus the chip row
with Tab — it is focusable and labelled "Active filters" — then use arrow keys/scroll).
Chips are never truncated with a "+N" overflow indicator and never wrap onto a second line.

### 7. Mobile map view regression (bottom sheet unchanged)

1. Resize to 375×812 (or use device emulation) and open Data in map view.
2. Note the Filters button at the bottom-left, apply a search that matches a subset, and
   compare the badge to the number of matching observations. Open and close the sheet
   (Categories row, search, dates, Apply, `✕`, outside tap).

**Expected:** the Filters button sits bottom-left with a badge equal to the **matching
result count** (not the dimension count — this is intentionally different from desktop).
The sheet opens as a **bottom sheet** with a drag handle, `rounded` top corners, max
height ~85vh — not a right drawer. No compact line/chips appear on mobile map view.

### 8. Grid view regression (desktop)

1. At ≥ 1024px, switch Data to **grid view**.
2. Exercise search, From/To, the inline category chip multi-select ("Filter by category"
   group), sort, "Clear filters", pagination, and the export button.

**Expected:** identical to main before this PR: the full multi-control filter bar renders
inline (search + From + To + category chips + sort + result count), with **no** compact
line, no Filters button, and no drawer. Category selection is inline in grid view, not
behind a sheet.

## Failure conditions

Mark the QA failed if any of these occur:

- Any search/date/category input renders on the desktop map line outside the drawer.
- The desktop Filters drawer renders as a bottom sheet, or is narrower/wider than the
  viewport-height right panel described above, or slides in from the left/bottom.
- Opening category selection inside the desktop drawer covers the whole screen (viewport
  bottom sheet) or dims/captures the whole page so the map is unusable.
- The drawer fails to close on Apply, ESC, or outside-click.
- A chip `✕` opens the sheet, removes the wrong filter, removes all categories when only
  one category chip is dismissed, or does not update the result count.
- The chip row wraps to a second line, hides the Filters button or the result count at
  ~800px, or truncates chips behind a "+N" affordance.
- The desktop badge equals the result count, counts each selected category separately,
  exceeds 4, or shows when nothing is filtered.
- Mobile map view shows chips/a compact line, opens a right drawer, or shows a
  dimension-count badge instead of the result count.
- Grid view loses the inline category multi-select, sort control, or any prior filter
  control.
- Two filter sheets/dialogs render at once (e.g. duplicate "Filters" dialogs on screen).

## Known limitations / intentionally untestable surfaces

- **jsdom cannot verify layout.** Chip overflow (`min-w-0 overflow-x-auto` + nowrap),
  drawer geometry, z-order, and the "does not cover the screen" property are CSS/layout
  outcomes; unit tests assert the classes and DOM structure only. Steps 3 and 6 above are
  the human verification of those invariants.
- **The 48rem breakpoint is only reachable in a real browser.** Unit tests mock
  `useMediaQuery`; the actual crossing of the breakpoint (resize from 760px → 780px
  swapping bottom sheet ⇄ right drawer) is covered here by manual resize, not automation.
- **Animation timing/quality** (slide-in-right 200ms, fade-in overlay) is not asserted by
  tests; verify it only does not glitch, trap focus, or leave the page inert.
- **No new persistence, network, or export behavior** is introduced, so there is no data
  reset, credential, or offline-safety surface to verify in this QA.
- **Screen readers:** chips and the badge have accessible names ("Remove filter: …",
  "N active filters"), but full screen-reader walkthrough (NVDA/VoiceOver) is not part of
  this pass; the chip row is keyboard-scrollable and focusable, which is the verified
  keyboard surface.
- **Storybook visual baselines** for the Data screen change with this PR; baseline review
  happens in CI (`visual-regression-check`), not in this manual script.

## Cleanup / reset

No data is written by this feature. To reset state between passes: clear filters with
the drawer's **Clear filters** (inside the sheet) or reload the page, which restores
`DEFAULT_FILTERS`. No localStorage/IndexedDB cleanup is required.
