# QA script — issue #337 sync button (PR adds manual sync triggers)

## Scope

Manual sync triggering surfaces added by this PR:

1. Per-archive "Sync Now" from the desktop `ArchiveBrowser` overflow sheet.
2. Per-archive "Sync Now" from the mobile nav drawer overflow sheet.
3. Global "Sync all" button in the topbar (all viewports), with aggregate outcome toast.

Outcome-toast mapping for sync results (success / partial / per-errorCode toasts, toast actions) and the new toast action affordance are in scope. Auto-sync (5-minute poll), the sync coordinator itself, per-project sync, progress UI, and the existing `ArchiveServerDetail` / `ArchiveStatusCard` sync buttons are NOT in scope (unchanged).

## Prerequisites

- A comapeo-cloud archive server reachable from the deployment under test.
- A signed-in session with at least one configured archive (server added, onboarding not cancelled).
- A second device/archive producing new observations, so a sync has data to pull — OR a deliberately broken server (wrong token / stopped server) to exercise failure toasts.
- Browser at desktop width (>=1024px) and mobile width (e.g. 375px) for the two sheet surfaces.

## Steps and expected results

### A. Global Sync all button — visibility

1. Sign in with zero eligible archives (no servers, or all onboarding cancelled).
   - Expected: NO "Sync all" button in the topbar; on screens that supply no other topbar actions, no divider renders either.
2. Add a credentialed archive (or complete onboarding on an existing one).
   - Expected: "Sync all" button appears in the topbar without a reload, at both desktop and mobile widths.

### B. Global Sync all — happy path

1. With new data available on the remote, click "Sync all".
   - Expected: button disables and shows a spinner with `aria-busy="true"`; label changes to "Syncing…".
2. Wait for completion.
   - Expected: exactly ONE toast: success ("All archives synced") when every eligible archive synced; clicking again mid-sync does nothing (no second toast, no duplicate calls in the network tab).

### C. Global Sync all — failure paths

1. Take one archive's token invalid (re-login flow or server-side revoke), then click "Sync all".
   - Expected: error toast with the "N of M archives synced" count summary. Per-archive state on Home reflects the failure.
2. Point an archive at an unreachable URL, then click "Sync all".
   - Expected: error toast (connection failure copy), count summary, no crash; button re-enables after completion.

### D. Per-archive Sync Now — desktop overflow sheet

1. On desktop, open an archive's overflow sheet in the left ArchiveBrowser pane and tap "Sync Now".
   - Expected: sheet closes immediately; sync starts for that archive only (single request to that server in the network tab); on completion one toast names that archive ("Archive synced — {name}").
2. Tap "Sync Now" again while that archive shows "Syncing…".
   - Expected: nothing happens — no extra network call, no toast.

### E. Per-archive Sync Now — mobile nav drawer

1. At mobile width, open the nav drawer, find the archive's overflow sheet, tap "Sync Now".
   - Expected: identical behavior to D (close + one toast + guarded re-entry). The menu item is comfortably tappable (>= 44px touch target).

### F. Toast actions (recovery paths)

1. Trigger an auth-expired failure on one archive (e.g. expire its session server-side), sync that archive.
   - Expected: error toast carrying a "Reconnect" action button that navigates to that archive's detail/reconnect screen. This toast stays ~10 s (not the default 5 s).
2. Trigger a storage-cleanup-required state if reproducible (else verify via the aggregate path in C).
   - Expected: info toast with an "Open Settings" action navigating to Settings.

## Failure conditions (any one fails QA)

- More than one `syncRemoteArchive` request per user action (double-fire), or any request issued while the server is already syncing or has no token.
- A success toast shown when a server actually failed, or an error toast on a fully successful sync (feedback fabrication).
- Two mounted "Sync all" buttons, or the button rendering when zero archives are eligible.
- Topbar divider appearing on a screen with no topbar actions when no archives are eligible.
- Toast actions missing, mis-navigating, or toasts auto-dismissing before the action can be tapped (< 44px action target).
- The 5-minute auto-sync behavior changes (auto-sync toasts must never appear from auto-sync runs).

## Cleanup

- Restore any revoked/changed tokens or server URLs used in failure tests.
- Remove any test archive created for the visibility checks (optional; dev data).

## Limitations / intentionally untestable by hand here

- `worker-transition-required` toasts depend on the storage-reset/app-update lifecycle and are not reliably reproducible manually; they are covered by unit tests.
- Coordinator-level dedup (concurrent manual + auto sync sharing one execution) is covered by `tests/unit/lib/sync-coordinator.test.ts`, not by this QA pass.
- StrictMode double-invoke toast-replay and mid-sync unmount behavior are unit-tested (hook-local state; no stuck `isSyncing` after remount) and not observable via manual UI testing.
