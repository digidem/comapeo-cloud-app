# QA Script — Issue #269: Case evidence selection and disclosure foundation

Issue: #269

## Scope

This QA validates the issue #269 evidence-selection and disclosure foundation used by Cases:

- add observations from Data and alerts from Alerts to an existing or newly created Case
- browse and add observations, alerts, and tracks from the Case Evidence tab
- keep Case evidence as provenance references to project source records rather than duplicating factual payloads
- preserve and explicitly surface changed, deleted, unavailable, and unsynced source state
- select photo/audio attachments independently from the parent source
- retain selected-media warning state if the source attachment later changes or is deleted/unavailable
- show selected evidence as list, timeline, and internal Case map views
- persist independent disclosure decisions per agency for reporter identity, people, location, media, and other sensitive fields
- default disclosure fail-closed (`reporter=omit`, `location=omit`, candidate decisions excluded)
- ensure `Area only` never derives/rounds exact source coordinates and only accepts an independently approved generalized geometry
- create metadata-scrubbed disclosure derivatives with original→derivative hashes and never fall back to raw original bytes for unsupported media
- keep Case activity metadata-only and prevent coordinates/media hashes from leaking into activity records
- remain local-only in this issue: no Case/provider upload or AI transcription/interpretation calls
- render correctly at 1440×900 and 375×812

This issue does **not** implement report templates/final PDF generation, remote Case sync, R2 report upload, or AI media interpretation/transcription. Those remain later child issues.

## Human / live-preview acceptance checklist

### 1. Data and Alerts entry points

- In Data grid view, select one or more observations; **Add to case** becomes enabled.
- Add the selection to an existing Case and confirm the dialog closes only after the operation succeeds.
- Repeat from Alerts grid view for an alert.
- Use **New case** in the dialog and confirm the minimal Case can be created and receives the selected source.
- Switching projects must not carry selected source IDs into the new project.

### 2. Case Evidence browser

- Open the Case and select **Evidence**.
- Confirm project observations, alerts, and tracks can be searched/filtered and individually added.
- Confirm the selected count reflects real linked evidence.
- Confirm List, Timeline, and Map views render the selected evidence without horizontal overflow on desktop and mobile.
- Confirm adding a source does **not** automatically select its photo/audio attachments.

### 3. Changed / deleted / unavailable / unsynced evidence

Using seeded/local QA data or IndexedDB tooling where appropriate:

- Change an already-selected observation version/update timestamp and confirm **Changed since added** appears.
- Mark the source dirty/local and confirm **Not project-synced** appears.
- Mark a selected source deleted and reload; confirm its last-known local label remains visible with **Deleted at source** rather than degrading to an opaque ID.
- Remove/unavailable a selected source record entirely and confirm the Case reference remains with an explicit unavailable warning.

### 4. Attachment independence and privacy state

- Select a photo/audio attachment under a selected observation and confirm the checkbox persists.
- Change its hash/update state and confirm **Media changed since selected**.
- Mark it deleted/unavailable and confirm the selected row remains visible with the explicit warning and can still be deselected.
- Verify no attachment becomes selected merely because the parent observation was added to the Case.

### 5. Disclosure controls

- Open **Reports** and select FUNAI.
- Confirm the initial state is fail-closed: reporter omitted, location omitted, all candidate people/media/sensitive fields excluded.
- Set reporter identity to Include, location to Area only, and include one selected media item; save.
- Switch to another agency and confirm its decisions remain independently fail-closed.
- Return to FUNAI and confirm its saved revision/choices persist.
- Confirm `Area only` does not synthesize rounded/derived coordinates; without an explicitly approved generalized boundary it emits no map geometry.

### 6. Metadata-scrubbed derivatives

Automated fixtures must prove:

- supported photo/audio inputs produce new derivative bytes, not the raw original
- EXIF/GPS/device metadata and supported audio metadata are absent from derivatives
- original and derivative SHA-256 hashes are both recorded
- unsupported/invalid formats fail closed and return no shareable original bytes
- raw originals remain source/local-cache data and are not part of reporting upload state in #269

### 7. Metadata-only activity and local-only boundary

- Open **Activity** and confirm evidence/media/disclosure events are present after the actions above.
- Inspect stored activity rows and confirm they contain only opaque Case/project IDs plus event/status/agency/count/timestamps as applicable—not source labels, tags, coordinates, geometry, report text, or media hashes.
- In browser network tooling, repeat Case evidence/disclosure changes and confirm there are no Case API, provider, OpenAI, Anthropic, Groq, or reporting-upload requests caused by #269.

### 8. Responsive and localization

At minimum verify 1440×900 and 375×812:

- tabs remain usable with no horizontal page overflow
- Evidence browser, selected evidence, attachment rows, disclosure controls, and dialog remain readable/tappable
- English, Portuguese, and Spanish strings load for the new #269 surfaces without raw message IDs or missing-message errors
