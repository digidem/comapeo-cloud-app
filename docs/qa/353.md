# PR #353 technical QA — agent guidance and GPT-6 Astra defaults

## Scope

Validate that PR #353 changes repository agent/process guidance and reviewer/model defaults without changing production application behavior, and that the PR-cycle policy remains internally consistent after syncing current `main`.

This PR has no production UI/runtime feature to click through. Human QA is therefore a technical repository-policy procedure.

## Prerequisites

- Check out PR #353 at its exact current head SHA in a clean worktree.
- Fetch the current `main` branch before running the checks.
- Python 3, Node.js, and repository dependencies are available.
- Run commands from the repository root.

## 3. Verify GPT-6 Astra policy wiring

Confirm all of the following on the exact PR head:

- `AGENTS.md` sets Codex default model to `gpt-6-astra` for planning, implementation, specification, debugging, and independent review.
- `.agents/skills/pr-cycle/SKILL.md` makes GPT-6 Astra via Codex the default independent reviewer, requires read-only exact head/base-tip review, and preserves the explicit named-model no-substitution rule.
- `.agents/skills/pr-cycle/references/gpt-6-astra-review.md` exists and defines terminal-verdict, exact-revision, timeout/resume, and fallback semantics.
- `.agents/skills/issue-to-spec/SKILL.md` uses GPT-6 Astra as the default high-risk spec reviewer.
- `WORKFLOW.md` configures Codex with `model="gpt-6-astra"`.
- `scripts/review-mobile-visuals.ts` uses `gpt-6-astra` and contains no stale `gpt-5.4-mini` model default.
- Fallback order remains Astra → Opus 5 → Kimi K3 → Qwen 3.8 when no exact named-model requirement blocks substitution.

Failure condition: contradictory model defaults, silent fallback to an older GPT model, stale model identifiers in active entrypoints, or weakened exact-revision review requirements.

## 4. Verify local-first and cleanup guidance

Confirm:

- `AGENTS.md` documents synchronous TanStack Query cache update from the canonical persisted record before invalidation for offline read-after-write behavior.
- `.agents/skills/pr-cycle/SKILL.md` treats a non-zero forge merge exit as ambiguous until live PR state is re-read.

Failure condition: guidance permits blind merge retries, broad force deletion, or cache-only/UI-only representations that diverge from canonical persisted records.

## 5. Exact-SHA reviewer and GitHub gates

After pushing the final head:

- Run a fresh read-only GPT-6 Astra via Codex review against the exact pushed head SHA and current live `main` tip.
- Require a terminal verdict with no blockers or should-fix findings.
- Require all relevant GitHub checks for that exact head SHA to be terminal green and no unresolved actionable review threads to remain.

Failure condition: stale reviewer coordinates, partial/nonterminal reviewer output, pending/failing relevant checks, unresolved actionable review feedback, or base-tip movement after the final review.

## Cleanup/reset

No runtime data or external service state is modified by this QA procedure. Remove only incidental local Python cache files or generated artifacts created by the checks; do not clean unrelated worktrees or branches.
